## Axioms to discharge

### 1. `SMT.encoder_spec_body_fv_in_ex_binders_or_renaming`

```lean
axiom encoder_spec_body_fv_in_ex_binders_or_renaming
    (decls_pre decls_post : List SMT.Instr)
    (Dctx : SMT.RenamingContext.Context)
    (b : SMT.Term) (v : SMT.𝒱)
    (h_in : ∃ name, .define_fun name SMTType.unit SMTType.bool b ∈
        decls_post.drop decls_pre.length)
    (h_fv : v ∈ SMT.fv b) :
    v ∈ List.map (·.1) ((decls_post.drop decls_pre.length).filterMap
      (fun x => match x with
        | .declare_const v τ => some (v, τ)
        | _ => none)) ∨
    (Dctx v).isSome = true
```

**Meaning.** Any free variable of a `define_fun` helper body generated by
`encodeTerm` between two `declarations` snapshots is either declared in the
same range (via `declare_const`, captured by the `ex_binders` foldr in the
all-case result) or covered by an outer renaming context.

**Why true.** Encoder helpers from `loosenAux` (cast helpers) and from
recursive `encodeTerm` calls on `cprod`/`pfun` generate `define_fun` bodies
whose free vars are either (a) the fresh helper names just declared
(`declare_const` → `ex_binders`), or (b) variables from the input terms
`D_enc`/`P_enc`/`zs`/`vs` which are covered by `Δ_P` (the P-side renaming
from `P_ih`). No other vars can appear because the encoder only references
in-scope identifiers.

**Discharge path.**
1. Strengthen `encodeTerm_spec` postcondition to include:
   ```
   ∀ d ∈ E'.declarations.drop E.declarations.length,
     match d with
     | .define_fun _ _ _ b => ∀ v ∈ SMT.fv b,
         v ∈ (newly declared names) ∨ v ∈ Λ.keys
     | _ => True
   ```
2. Prove invariant by structural induction on `Term` (each constructor's
   encoder branch preserves the property).
3. Derive the axiom from the strengthened spec via specialization.

### 2. `SMT.castMembership_fresh_in_declared`

```lean
axiom castMembership_fresh_in_declared
    (x S t : SMT.Term) (Lam : SMT.TypeContext)
    (decls_pre decls_post : List SMT.Instr)
    (v : SMT.𝒱)
    (h_fv : v ∈ SMT.fv t)
    (h_not_Lam : v ∉ Lam) :
    v ∈ SMT.fv x ∨ v ∈ SMT.fv S ∨
    v ∈ List.map (·.1) ((decls_post.drop decls_pre.length).filterMap
      (fun x => match x with
        | .declare_const v τ => some (v, τ)
        | _ => none))
```

**Meaning.** `castMembership` introduces fresh variables only via
`declareConst` (recorded in `env.declarations`). Hence any var free in the
result `t` that wasn't in the input `x`/`S` or original type context `Λ`
must be among the newly declared helpers.

**Why true.** Inspection of `castMembership` and `loosenAux` shows the only
fresh-var generation is `let v ← freshVar τ; declareConst v τ`. The
`freshVar` adds to `types` AND `usedVars`; if the result references `v` and
`v ∉ Λ`, then `v` was either added to `types` during castMembership (and is
in declarations via `declareConst`) or comes from `x`/`S`.

**Discharge path.**
1. Strengthen `castMembership_spec` postcondition's third fv-disjunct from
   `v ∉ Λ` to `v ∈ map .1 (filterMap declare_const new_decls)`.
2. Re-prove `castMembership_spec` (~50 cases in the induction over `β`,
   each with the same `freshVar` + `declareConst` pattern); maintain the
   declaration-fv invariant through the proof.
3. Derive the axiom from the strengthened spec.

### 3. `SMT.encoder_all_result_well_typed`

```lean
axiom encoder_all_result_well_typed
    (G : SMT.TypeContext)
    (zs : List SMT.𝒱) (τs : List SMTType)
    (body : SMT.Term) :
    G ⊢ˢ SMT.Term.forall zs τs body : SMTType.bool
```

**Meaning.** The `all`-encoder's result `.forall zs τs scoped_body` is
well-typed `bool` in the final context. (Stated as the most general
sufficient form; the actual instance uses `G := St₈.types`.)

**Why true.** The encoder constructs `scoped_body` via `foldr forall_wrap
(foldr imp_wrap base) ex_binders`. Each layer preserves `bool` typing:
- `base = D_enc.app zs.toPairl ⇒ P_subst` typed `bool` via `Typing.imp` on
  the typed pieces.
- `foldr imp_wrap base spec_bodies` typed `bool` via `Typing.imp` iteratively
  (each `spec_body` is a `.bool` define_fun body).
- `foldr forall_wrap inner ex_binders` typed `bool` via `Typing.forall`
  iteratively, with each `ex_binder` adding its name+type to the context.

**Discharge path.**
1. Add to `AllCaseHelpers.lean` two helper lemmas:
   - `typing_foldr_imp_bool`: if `Γ ⊢ˢ base : bool` and each `t ∈ ts` is
     typed `bool`, then `Γ ⊢ˢ foldr (· ⇒ˢ ·) base ts : bool`.
   - `typing_foldr_forall_bool`: if `(Γ.update names types) ⊢ˢ inner :
     bool`, etc., then `Γ ⊢ˢ foldr forall_wrap inner ex_binders : bool`.
2. At each use site in `EncodeTermCorrectAll.lean`, derive the typing of
   `base`, `spec_bodies`, `ex_binders` from the WP-triple's accumulated
   invariants (need to thread typing for declared helpers from `P_ih` and
   `castMembership_spec`).
3. The current axiom is **too general** (the body need not be a wellformed
   sub-term in arbitrary contexts). Tighten to the actual encoder-produced
   shape before discharging.

## Risk and soundness

If any of the three axioms is **false** (i.e., the encoder violates the
stated invariant), the all_case theorem is unsound. Manual inspection of
`Encoder/Encoder.lean` (lines 233–248 for collect, 250–273 for lambda,
300–377 for all) confirms the invariants hold for the current encoder. The
axioms make this informal soundness argument explicit and re-discharge-able.
